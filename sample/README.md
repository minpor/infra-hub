# Infra Hub — интерактивный HTML sample

Локальный прототип по направлению «Своя мощность»: яркий синий, графит, Unbounded / Onest / IBM Plex Mono. Все данные и операции демонстрационные. Backend, SSH, Git, Docker и настоящий MCP-сервер не подключены.

## Открыть

Откройте [index.html](index.html) в современном браузере. Ничего устанавливать не нужно: стили, JavaScript, шрифты, знак и лицензии встроены в один файл. Файл можно скопировать и открыть без сети.

Для просмотра через локальный HTTP из корня проекта:

```bash
python -m http.server 4173 --bind 127.0.0.1 --directory sample
```

Затем откройте [локальный пример](http://127.0.0.1:4173).

## Что можно попробовать

- Подключить демо-проект, изменить репозиторий, добавить окружение и обычные переменные.
- Настроить pipeline: Dockerfile или команды, добавить, удалить и переставить шаги, выбрать исполнителя, кеши и лимиты ресурсов. Команды сохраняются как текст и не исполняются.
- Запустить сборку с успешным результатом, ошибкой тестов или публикации; посмотреть шаги, логи, тесты, манифест артефакта; отменить или повторить запуск.
- Выложить готовую версию в выбранное окружение с подтверждением production. Проверить неуспешный health check и возврат предыдущей версии.
- Искать по проектам, IP, доменам, базам, Xray, commit и номерам сборок.
- Добавить карточку сервера или запись домена, выполнить демо-опрос, посмотреть связи ресурсов, расширения PostgreSQL и отметить демо-бэкап.
- Настроить MCP-права пространства и клиента, создать и отозвать демо-доступ, добавить внешнее подключение и смоделировать проверку.
- Через «Демо-вызов» проверить разрешённые и запрещённые действия MCP и результат в журнале.
- Переключить тему, поставить симуляцию на паузу, изменить её скорость и сбросить данные.

Симуляция запускается с паузы, чтобы первоначальные состояния можно было рассмотреть. Новая сборка или деплой включает её автоматически. При перезагрузке выполнение снова ставится на паузу; состояние сохраняется.

## Хранение и границы

Изменения хранятся в `localStorage` браузера под ключом `infra-hub-sample-v1`. Если браузер запрещает сохранение, интерфейс продолжает работать в памяти и показывает ограничение в подвале. Для `file://` поведение хранения зависит от браузера; данные при открытии через HTTP и напрямую могут различаться.

«Сбросить демо» возвращает исходное состояние. Никакие команды не выполняются, адреса внешних сервисов не запрашиваются. Создаваемые доступы имеют префикс `DEMO_ONLY_` и не являются настоящими токенами. Ссылки на секреты сохраняются только как имена; действующие ключи и пароли вводить не нужно.

В симуляции сборка и рабочая версия приложения разделены. Ошибка сборки или health check сохраняет рабочую версию. Выпуски одного окружения не выполняются одновременно. Созданная сборка хранит снимок параметров pipeline. Проверка MCP ограничивает вызовы проектами, сроком, состоянием доступа и совместными правами пространства и клиента.

Это сценарии прототипа, не гарантии backend или изоляции исполнителей. Произвольные команды pipeline не интерпретируются: анимация использует четыре демонстрационных этапа. Автодеплой по push, расписания и настоящие проверки состояния не подключены.

## Исходники и пересборка

- `src/shell.html` — оболочка документа.
- `src/style.css` — адаптивный интерфейс и две темы.
- `src/app.js` — данные, навигация, формы и симуляция.
- `src/fonts.css`, `assets/fonts/` — настоящие локальные шрифты и SIL OFL.
- `assets/infra-hub.svg` — векторный знак для прототипа.

После изменений:

```bash
python sample/build.py
```

Сборка использует только стандартную библиотеку Python. Лицензии шрифтов включаются в итоговый HTML.

## Проверка

`tests/smoke.cjs` проверяет пользовательские сценарии и автономную работу. `tests/layout.cjs` проверяет разделы и формы на ширинах 320, 390, 768, 1280 и 1440 px. Для запуска нужен доступный пакет `playwright` и установленный Chrome; путь к Chrome можно передать через `CHROME_BIN`.

```bash
node sample/tests/smoke.cjs
node sample/tests/layout.cjs
```
